# Roomly. Результаты проверки

Проверена [форма бронирования](https://rcsi-science.github.io/demo-roomly/) 25 ноября 2026 года. Требования и каркас взяты из [задания РЦНИ](https://github.com/rcsi-science/demo-roomly/tree/403f770daac0dbe4fa1f22153b890aaa39c91b52).

Обычная бронь, вместимость и обязательные поля работают по требованиям. Форма подтверждает бронь с неверной длительностью, на прошедшее время текущего дня и с дробным числом участников.

## Ручная проверка

Базовые данные для проверки каждого изменения: завтра, 10:00–11:00, комната «Малая», 4 участника, Анна Тестова, `anna@example.com`. В таблице указаны отклонения от них. ## Дефекты

У каждого дефекта остальные поля заданы базовыми данными. Фразы и строки ниже записаны из интерфейса.

### BUG-01. Форма подтверждает бронь за пределами допустимой длительности

1. Выбрать «Большую», одного участника и дату на завтра.
2. Указать начало 10:00, окончание 10:29 и нажать «Забронировать».
3. Повторить с окончанием 14:01.

**Ожидаемо.** Форма отклоняет оба интервала и сообщает о допустимой длительности от 30 минут до 4 часов.

**Фактически.** Появляется «Бронирование создано.» и строка `Большая, 2026-11-26, 10:00–10:29 · Анна Тестова`. Для 14:01 показано такое же подтверждение с интервалом `10:00–14:01`. Контрольные значения 10:30 и 14:00 принимаются.

**Приоритет P1.** Нарушаются обе границы основного правила бронирования. Нижнюю границу покрывает автотест с `xfail`.

### BUG-02. Можно забронировать комнату на прошедшее время текущего дня

1. После 11:00 по местному времени выбрать сегодняшнюю дату, «Большую» и одного участника.
2. Указать интервал 10:00–11:00 и нажать «Забронировать».

**Ожидаемо.** Форма отклоняет заявку и сообщает, что время уже прошло.

**Фактически.** 25 ноября после 20:58 МСК форма показала «Бронирование создано.» и `Большая, 2026-11-25, 10:00–11:00 · Анна Тестова`. Аналогичный интервал за вчера был отклонён.

**Приоритет P1.** Пользователь получает подтверждение на встречу, время которой уже прошло.

### BUG-03. Одинаковое время начала и окончания принимается

1. Выбрать «Большую», одного участника и дату на завтра.
2. Ввести 10:00 в поля начала и окончания, нажать «Забронировать».

**Ожидаемо.** Форма отклоняет заявку. Окончание должно быть позже начала.

**Фактически.** Появляется «Бронирование создано.» и `Большая, 2026-11-26, 10:00–10:00 · Анна Тестова`. Контрольный вариант с окончанием 09:59 отклоняется с сообщением «Время окончания должно быть позже начала.».

**Приоритет P1.** Подтверждается бронь с нулевой продолжительностью.

### BUG-04. Форма принимает дробное число участников

1. Выбрать «Большую» и дату на завтра.
2. Указать 10:00–11:00 и вручную ввести `1.5` в поле «Участники».
3. Нажать «Забронировать».

**Ожидаемо.** Появляется ошибка. Количество участников вводится целым числом.

**Фактически.** Поле сохраняет `1.5` и показывает «Бронирование создано.».

**Приоритет P2.** Форма принимает неверные данные о количестве людей. Ограничения по вместимости для целых значений работают.

## Вопросы, допущения и ограничения

- Какой часовой пояс определяет текущий день и прошедшее время? В проверке использовалось местное время браузера. Прошедший интервал выбран с запасом в несколько часов.
- Есть ли ограничения на домен рабочей почты? По заданию проверялся формат. В качестве адреса для тестирования использован `example.com`.
- Допустимы ли встречи через полночь и есть ли рабочие часы офиса? В проверке встреча начинается и заканчивается в один день.
- Количество людей считается целым числом. Границы 30 минут и 4 часа включены.
- Ручная проверка выполнена на опубликованном демо в настольном браузере. Мобильные устройства, другие браузеры и прохождение полуночи при открытой форме остались вне проверки. Сброс проверялся обычной перезагрузкой.

## Автотесты

Из корня репозитория с Docker Compose v2:

```bash
docker compose run --build --rm tests
```

Альтернативный запуск с Python:

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest
```

Тесты по умолчанию обращаются к опубликованному демо. Для другого стенда можно передать `--base-url URL` при запуске `pytest` или задать `BASE_URL` перед запуском Docker Compose. Отчёт пишется в `artifacts/junit.xml`, диагностика браузера — в `artifacts/browser/`.

| Тест | Проверка |
| --- | --- |
| `test_successful_booking` | Четыре участника в «Малой». Подтверждение содержит комнату, дату, время и имя |
| `test_rejects_booking_over_room_capacity` | Пять участников в «Малой». Общий отказ и сообщение о вместимости |
| `test_rejects_booking_shorter_than_30_minutes` | Бронь на 29 минут должна отклоняться. `xfail(strict=True, raises=AssertionError)` связан с BUG-01 |

Дата вычисляется на момент запуска с запасом в два дня. `xfail` применяется к проверке правила. Ошибка загрузки страницы, отсутствие элемента или неожиданный ответ формы прерывают тест обычным падением. После исправления BUG-01 строгий `xfail` подсветит результат `XPASS`, после чего отметку можно снять.

**Окружение и результат.** Ручной прогон проведён на macOS 27.2.1 (arm64) во встроенном браузере ChatGPT. Версия его движка в интерфейсе недоступна. Три сценария и их селекторы дополнительно сверены в браузере на тех же данных. Локально подтверждена компиляция Python-файлов. Docker Compose v2.40.3 установлен, подключение к Docker в текущем окружении ограничено. Ожидаемый результат полного запуска `pytest` вместе с исходным smoke-тестом — `3 passed, 1 xfailed`.

**Затраченное время.** Около 12 минут на проверку формы, написание трёх тестов и подготовку отчёта. Настройка окружения и публикация учитываются отдельно.
